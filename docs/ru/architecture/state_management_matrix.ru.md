## Инструменты рукописи

BrightnessDraftCubit и ReplacementDraftCubit используют сравнимые записи Dart. Окно освобождает свой Cubit при закрытии. После пипетки новое окно берёт актуальные значения из модели просмотра.

## Доступность номеров Стронга в модуле

`BibleModuleDB.readInfo` определяет `BibleModuleInfo.hasStrongNumbers` по отдельным токенам G/H с цифрами в тексте всех стихов. SQL отбирает кандидатов ограниченными пакетами, проверка использует общий с чтением контракт токена; сноски не учитываются. Признак входит в сравнение значения и обновляется при чтении сведений о модуле без изменения SQLite-схемы или постоянного кеша. Каждая панель выводит доступность кнопки и пункта меню Стронга из своего `selectedModule`; дополнительного флага видимости в состоянии нет. Выбор показа номеров сохраняется при переходе через текстовый модуль, а самостоятельный словарь остаётся доступным.

## Информация о модуле в состоянии чтения

`BibleReaderState.selectedModule` остаётся единственным снимком выбранного модуля в каждой панели. Его значение `BibleModuleInfo` теперь включает необязательные версии данных/схемы и дату ревизии; сравнение и хеширование учитывают все три значения. Начальная загрузка и смена модуля передают ревизию через существующий защищённый асинхронный поток. Открытие информации не выполняет I/O или запись состояния; панель инструментов и меню используют один диалог.

## Параллельное чтение по умолчанию и по ссылке

При входе из меню `BibleWorkspaceCubit` восстанавливает из локальных настроек порядок панелей, переводы, выделение, видимый стих каждой панели и режим связанной навигации. При первом входе используется прежний список модулей либо LXX/TR и перевод по умолчанию. Внутренняя библейская ссылка открывает диалог отрывка. Нижняя кнопка диалога и прямая ссылка на читалку показывают отрывок во всех панелях на время просмотра. Если указанный в ссылке модуль отсутствует, он временно занимает первую панель. При следующем входе из меню читатель возвращается к обычным местам.

При входе в словарь Стронга из меню `StrongsDictionaryCubit` восстанавливает локально сохранённый номер статьи и прокрутку. Переход по номеру на полную страницу сразу сохраняет открытую статью с начала текста. Прокрутка обновляет сохранённую позицию. На странице словаря перекрёстная ссылка открывает и сохраняет новую статью на месте. В первоисточнике панель описания ведёт собственный выбор и подсвечивает совпадающие номера на листе. Просмотр в этой панели или в диалоге другого раздела сохраняет место последнего посещения полной страницы. Если сохранённая статья недоступна, словарь открывает первую доступную статью.

Обычный `/bible` восстанавливает сохранённый набор панелей (включая legacy-выбор одного модуля). `bible:` и `/bible` с параметрами ссылки открывают исходную книгу/главу/стих и перевод независимо от сохранённой раскладки; формат существующих маршрутов сохранён. Автоматическое открытие и навигация не записывают настройки. Только явное добавление/закрытие панели или успешная смена модуля сохраняют полный готовый набор. Workspace — единственный владелец записи; ReaderCubit больше не записывает общий single-module preference. Записи выполняются последовательно, незагруженные панели не сохраняются. Начальная загрузка объединяется, закрытие и ручное изменение раскладки отменяют применение запоздалого автоматического подбора. Режим связанной навигации по-прежнему относится к текущему workspace. Подбор перевода выполняется один раз; после медленной загрузки новая панель получает актуальную ссылку основной, дожидаясь текущей синхронизации.

## Состояние поиска аллюзий и каталога Библии

Состояние поиска хранит исходный текст и перевод с разметкой. Отдельная проверка актуальности защищает оригинал при быстрой смене отрывка. Один неизменяемый индекс предоставляет веса, совпадения по стихам и оценку сходства. Список слов исходного отрывка раскрывается независимо от текста и карточек выдачи. Выбор другого отрывка сворачивает список его слов.

SettingsCubit сохраняет глобально выбранную Библию. BibleCatalogCubit сначала отдаёт модули из кеша, затем обновлённый каталог. AppDi предоставляет один AllusionSearchCubit на сессию приложения. Он сохраняет запрос, выдачу, вкладку и страницу при навигации и обновляет тексты после смены перевода. Каноническая карта доступна независимо от подготовки индекса. Фоновая подготовка и последующие поиски за одно посещение используют один запрос индекса. При новом входе проверяется редакция модуля, а после сбоя подготовки доступен повтор. При смене запроса, страницы или настроек проверка актуальности отбрасывает запоздалые ответы.

BiblePassagePreviewCubit управляет диапазоном стихов и двумя текстами. Стрелки сдвигают диапазон по карте канона. При сбое одного модуля остаётся доступным текст второго. После смены отрывка или закрытия диалога запоздалый ответ отбрасывается.

## Повтор первого открытия Библии

`BibleReaderCubit.retryInitialLoad` повторяет только неудачную начальную загрузку, сохраняя исходные параметры маршрута. Доступность кнопки выводится из failure и отсутствия verseMap; повторный запрос синхронно переводит Cubit в loading, поэтому быстрые нажатия объединяются. Существующий LatestRequestGuard защищает от устаревших ответов и завершения после close. Workspace, репозиторий и схема состояния остаются единственными владельцами своих данных; отдельное состояние повтора не вводится.

## Текстовые модули Библии и сноски

BibleReaderCubit остаётся единственным источником стихов главы, включая отдельные комментарии, для каждой панели workspace. Видимость действия выводится из загруженного комментария; дополнительного флага видимости или comment-cubit нет. Сравнение значений стихов учитывает comment, поэтому изменение сноски обновляет существующее представление по состоянию. Открытие/закрытие сноски — явное UI-действие диалога без побочного действия repository.

## Strong Feature Notes

- `StrongUsagePreviewCubit` — единственный источник текста и запросов показа подсказки одной ссылки; объединяет быстрые запросы и отбрасывает результат после закрытия при смене ссылки.
- `StrongsDictionaryCubit` является source of truth для выбора, контента, навигации и полнотекстового фильтра словаря Стронга в page/dialog-потоках.
- `StrongNumberPickerCubit` владеет нормализацией ввода и состоянием выбранного элемента в picker-е номера Стронга.

## Базовые правила

- `Cubit` является основным state-примитивом приложения.
- Состояние хранится в cubit-ах, а не в mutable-полях виджетов или feature-моделей.
- State-классы остаются immutable и comparable.
- Ошибки представляются через `AppFailure`.
- Если async-запросы могут гоняться между собой, побеждает самый новый запрос.

## Примечания по scope

- `RevelationStartupHost` создаёт `AppStartupCubit` в корне приложения и подключает глобальные app-провайдеры только после готовности startup-flow.
- Глобальные провайдеры создаются в `AppDi.appBlocProviders`.
- Общие markdown-виджеты создают `RevelationMarkdownImagesCubit` на уровне каждого markdown-документа, а не хранят markdown image preload state в feature-cubit-ах.
- `StrongsDictionaryCubit` является единственным source of truth для состояния выбора словаря Стронга в page/dialog-потоках; `primary_sources` только делегирует действия через API Strong-feature.
- `PrimarySourceScreen` поднимает detail cubit-ы через `MultiBlocProvider`.
- `PrimarySourceDetailCoordinator` адаптирует UI-события к detail cubit-ам и не владеет состоянием.
- `BibleWorkspaceCubit` владеет только page-level композицией панелей чтения; каждая панель хранит собственный текст Библии и выбор стихов в `BibleReaderCubit`.
